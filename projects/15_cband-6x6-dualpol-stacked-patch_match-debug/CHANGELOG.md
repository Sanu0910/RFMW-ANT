# Changelog: 15_cband-6x6-dualpol-stacked-patch_match-debug

Newest first.

## 2026-10-30
- Full-array run port 2 (H) finished (80 000 steps, -31.6 dB): S22 VSWR <= 1.8 at the 5.0-6.25 GHz spot frequencies, 2.7-5.6 outside; broadside realised gain 17.1 / 15.1 / 18.9 / 21.2 / 13.7 dBi at 4.5 / 5.0 / 5.5 / 6.0 / 6.5 GHz, gain vs accepted power almost the same. The simulated gain reproduces the measured shortfall and the drop above ~6.2 GHz, so the gain problem is in the design, not the radome or the test range. `03_results/array_p2_*`, `measured_vs_sim.png`. Port 1 still running.
- Option 1 (uniform 16.2 mm parasitics) and option 2 (wider feed start, lines >= 0.73 mm) both evaluated full-wave from the layer files: neither improves the element match (option 2: H 3.50 -> 3.67, V 3.59 -> 3.58 worst VSWR over 5.1-6.2 GHz; `03_results/opt2_vswr.png`, `opt2_summary.txt`). The first option-2 design had used the 60 mm-ground model, whose ground-edge effects overstated the as-built mismatch (4.6 instead of 3.5); `fixb_design.py` now starts from the infinite-ground as-built model of both feeds. `fix_parasitics.py` removed; `06_fixB/` keeps the option-2 layout with a NOT RECOMMENDED note.
- STEP model rebuilt from the as-built layers: `07_step/CBand_6x6_asbuilt_with_SMA.step` (52 bodies, all checks PASS).
- Feed-line width change (fixb_design.py: thin 0.25 mm and wide >= 0.73 mm versions) evaluated and rejected by the user ("keep the line same"); the line-modifying layout script was removed.
- Fix B (final, lines unchanged): `fix_parasitics.py` -> `06_fixB/` (F.Cu all 16.2 mm, In2.Cu and B.Cu identical to the input). Element study from the layer files (`sim_element_fix.py`, infinite ground): as built H feed worst VSWR 3.50 / V feed 3.59 over 5.1-6.2 GHz; parasitic 15.6-16.8 mm and gap 3.5-4.5 mm give no improvement; per-row sizes 16.2-17.8 mm form a stagger tuning (larger = better low band, worse high band) - `03_results/fix_rows.png`, `fix_rows.txt`.
- STEP model `07_step/CBand_6x6_fixB_with_SMA.step` (SolidCraft, 52 bodies, all volume checks PASS): ground, RT5880, In2.Cu, FR4, uniform parasitics, two 4-hole flange SMA jacks with centre pins at the launch points (`02_openems/build_step.py`). Renders `07_step/step_*.png`.
- VSWR fix within the existing build: `sim_tune.py` (parametric present element, infinite ground, dual-pol edge feeds, optional matching sections), `tune_match.py` (two-section / stub matching on the 100-ohm branch), `opt_tune.py`, `fix_figures.py` -> `03_results/fix_vswr.png`. Full-wave verified: fix A (72.5 ohm 1.36 mm x 6.74 mm + 150 ohm 0.25 mm x 12.07 mm) VSWR <= 3 about 4.98-6.22 GHz; fix B (91.9 ohm 0.86 mm x 6.11 mm + 150 ohm 0.25 mm x 12.85 mm) VSWR <= 2 about 5.17-6.17 GHz, worst 2.72 over 5.1-6.2 GHz. VSWR <= 2 over the full 4.9-6.4 GHz is not reachable by patch-size tuning in this stack-up (single radiating resonance, high sensitivity: 0.3 mm on L1 shifts the match strongly).
- Mesh fix: essential mesh lines (ports, edges) are no longer dropped by the thinning (a dropped port line gave zero excitation).
- "Measured results" section added to all three reports: engineering report section 6 (15 pages), client report 5.6 + root cause 6 + plan item 1b (10 pages), results-only report section 6 + status rows + client actions (6 pages). Shared table `client_report.measured_table()`.
